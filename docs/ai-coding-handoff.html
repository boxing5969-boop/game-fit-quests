5.5 "로딩 중…" 영구 노출 진단 미수정

핵심 결함 식별 — 미수정 상태로 진단만 마침

apps/crm/src/components/ProtectedRoute.tsx:8 의 분기 순서:

if (authLoading || profileState === "idle" || profileState === "loading") {
  return <로딩 중…>;
}
if (!user) {
  return <Navigate to="/login" />;
}

profileState === "idle" 의 의미 = "세션 없음(비로그인)". 그런데 그 상태가 로딩으로 잘못 분류되어, 비로그인 사용자가 보호 라우트를 직접 방문하면 /login 으로 리다이렉트되지 못하고 영구 "로딩 중…" 노출.

재현: localStorage 에 세션 없는 상태로 / 또는 /members 직접 진입. 새로고침해도 동일. /login 직접 진입은 정상(ProtectedRoute 밖).

특히 Cloudflare Pages preview URL ↔ production URL 간 origin 분리로 localStorage 세션이 공유되지 않을 때 confidently 재현.

권장 hotfix — 분기 순서 변경:

if (authLoading) return <로딩>;
if (!user) return <Navigate to="/login" state={{ from: location }} replace />;
if (profileState === "idle" || profileState === "loading") return <로딩>;
if (profileState === "error") return <에러 화면>;
if (profileState === "missing" || !profile) return <프로필 미연결>;
return <Outlet />;

  6. Solapi/Payssam API 키를 .env / Pages 환경변수에 노출하지 말 것. 모두 Workers wrangler secret 전용.

9.3 운영 DB 진단 SQL (Supabase SQL Editor)

-- (1) Phase 21 GRANT 적용 여부 확인
SELECT grantee, privilege_type
FROM information_schema.role_table_grants
WHERE table_schema = 'public' AND table_name = 'profiles' AND grantee = 'authenticated'
ORDER BY privilege_type;
-- 비어있으면 supabase/migrations/20260507000000_grant_authenticated_privileges.sql 적용 필요

-- (2) profiles RLS 정책 본문
SELECT polname, polcmd,
       pg_get_expr(polqual, polrelid)      AS using_clause,
       pg_get_expr(polwithcheck, polrelid) AS check_clause
FROM pg_policy WHERE polrelid = 'public.profiles'::regclass;

-- (3) 특정 사용자 프로필 직접 조회
SELECT id, role, company_id, branch_id, auth_user_id, name, created_at
FROM public.profiles WHERE auth_user_id = '<UUID>';

-- (4) RLS 활성 확인
SELECT relname, relrowsecurity FROM pg_class WHERE relname IN ('profiles','members','memberships');

-- (5) auth.users 에 있는데 profiles 매핑 누락된 계정
SELECT u.id AS auth_user_id, u.email, u.created_at
FROM auth.users u
LEFT JOIN public.profiles p ON p.auth_user_id = u.id
WHERE p.id IS NULL ORDER BY u.created_at DESC;

-- (6) payment_requests 테이블 존재 (운영 적용 확인)
SELECT to_regclass('public.payment_requests');
-- NULL 이면 20260510000000_payment_requests.sql 미적용
